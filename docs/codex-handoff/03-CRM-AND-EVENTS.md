# 03 — CRM & EVENTS

Status legend: **REAL** (working code, tested) · **MOCK** (works but generated/simulated data) · **PARTIAL** (some pieces) · **ABSENT** (not built).

## The CRM, end to end

| Capability | Status | Evidence |
|---|---|---|
| **Contacts + fields** | **REAL (thin)** | `Contact = { id, tenantId, name, email?, phone?, stage, createdAt }` (`src/crm/types.ts:24-32`). No company, owner, tags, custom fields, source, or consent. |
| **Pipelines + stages** | **REAL (fixed)** | Single hard-coded pipeline `['lead','contacted','qualified','won','lost']` (`src/crm/types.ts:13`); a contact holds one `stage`; counts derived in `tenantView` (`src/crm/store.ts:111-112`). No custom pipelines, no per-stage config. |

| **Activity timeline** | **REAL** | `Activity` typed events (`crm/types.ts:34-42`); written by store ops + bridges (see "Events" below); rendered newest-first in `tenantView` (`store.ts:113-115`) and on the dashboard (`src/portal/views.ts`). |
| **Lead capture sources** | **PARTIAL / MOCK** | Two inbound paths exist: `POST /api/subscribe` (scorecard lead → Brevo, `src/server/app.ts:152-161`) and `POST /api/intake` → provisioning. **Neither writes a CRM `Contact`.** The only contacts in the CRM are demo-seeded (`src/portal/provision.ts:120-126`). No web-form-to-contact, no inbound email/DM capture. |
| **Tasks / next actions** | **ABSENT** | No task entity anywhere. |
| **Appointments** | **ABSENT** | No calendar/appointment entity, booking, or availability. |
| **Conversations / messages** | **ABSENT (as data)** | No message/conversation store. `ActivityKind` has `'message_sent'` and `Channel` has `email/sms/whatsapp` (`crm/types.ts:9,11`) but nothing records a message body/direction/thread. Email *sending* exists (Postmark/Brevo) but is not modelled as CRM conversation. |
| **Consent / suppression** | **ABSENT** | No consent/opt-out/suppression fields or lists. |
| **Source / UTM attribution** | **ABSENT** | No `source`/`utm_*`/`referrer`/`campaign` on Contact or Activity. |
| **Won / lost values + revenue** | **ABSENT (in CRM)** | Pipeline is counts only; no monetary value on contacts/stages. Order `amount_total`/`currency` exist (`src/server/orders.ts:19-20`) and subscription plan is known, but neither is joined into the CRM or rolled up as revenue. |
| **API routes (CRM)** | **PARTIAL** | No REST CRUD for contacts/activities. The only client-facing CRM surface is the read-only dashboard (`GET /portal`, `src/portal/router.ts:85-90`) and `POST /portal/run` (`:127`). Contacts are created only server-side (seed + `store.addContact`). Full route list: `api-routes.txt`. |
| **UI screens** | **REAL (read-mostly)** | Portal dashboard renders pipeline + contacts table + activity feed + brand brain + artifacts (`src/portal/views.ts` `dashboardPage`); billing screen (`billingPage`). Admin renders runs/orders/pack (`src/server/admin/views.ts`). No contact-edit, deal, task, calendar, or inbox screens. |

### What's real vs mocked vs absent — summary
- **Real & working:** the tenant/contact/pipeline/activity data model and store (memory + JSON), the read-only portal dashboard, the admin control room, sign-off.
- **Mocked:** all portal content the client sees (brand brain, cluster, keywords, ads) is generated by the **mock LLM** by default (`src/portal/run.ts` uses `MockClient`); the seeded contacts/pipeline are demo data (`src/portal/provision.ts:111-126`).
- **Absent:** deals, tasks, appointments, conversations/messages, consent, attribution, revenue roll-up, contact dedup, contact CRUD API, any lead-form → contact path.

## Events, triggers, automations

### Is the timeline typed events or hand-written display rows?
**Typed business events.** Every entry is an `Activity` with a typed `kind` (`ActivityKind`) and `channel` (`Channel`) created through `store.addActivity` (`src/crm/store.ts:100-105`). There are no free-text-only "display" rows bypassing the model. What is composed per-event is the human-readable `summary` string. Caveat: the **demo seed** produces its timeline by calling the real store operations (`addContact`/`moveContact`/`runTickReal`), so even seeded entries are genuine typed events — but they describe **mock/demo activity**, not real customer interactions.

### Every event / trigger / automation that exists
| Trigger | Emits | Where |
|---|---|---|
| Contact created | `Activity{kind:'contact_created', channel:'system'}` | `src/crm/store.ts:85` |
| Contact stage moved | `Activity{kind:'stage_changed', channel:'system'}` | `src/crm/store.ts:95` |
| Manager tick ran a rail | `Activity{kind:'rail_run', channel: per-action}` via `ingestTick` (`skipped` entries dropped) | `src/crm/ingest.ts:20-33` |
| Portal "Run this week" | records rail-run activities for the tenant (mock generation) | `src/portal/run.ts` (`runTickReal`), route `src/portal/router.ts:127-133` |
| Intake accepted (`POST /api/intake`) | fires `onIntakeAccepted` → background provisioning (creates tenant/account, generates brand brain) — **fire-and-forget** | `src/server/app.ts:171-175`, `src/server/index.ts:158-165` |
| Stripe `checkout.session.completed` | records an `Order`; optional Brevo `onCustomer` sync | `src/server/app.ts:135-142` |
| Stripe `customer.subscription.*` / `invoice.*` | upserts a `Subscription` | `src/server/app.ts:144-148`, mapping `src/server/subscriptions.ts:120-137` |
| New tenant provisioned | optional `onProvisioned` → login email (Postmark) | `src/portal/provision.ts:149-153`, `src/server/index.ts:118-121` |

### What there is NO automation for
- No rules engine / workflow builder / "if X then Y" (no trigger DSL, no conditions).
- No scheduled automations beyond the **manually-invoked** manager CLI tick (no cron/queue — see `04-MANAGER-AND-RAILS.md`).
- No message send/receive automation, no drip/sequence engine (the roadmap's "autoresponder" is unbuilt).
- No lead-form submission → contact creation, no follow-up task creation, no appointment reminders.
- Events are **not durably logged as an event stream** — `rail_run`/provisioning hooks are fire-and-forget; failures are `console.warn` only (`app.ts:174`, `index.ts:157`), with no retry or dead-letter.
