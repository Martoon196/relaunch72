2. DESIGN APPROACH (SOURCE-TO-DESIGN)
- production-core is the only dependency of every specialist pack. It owns the claim
  ledger (verified brand fact / external source / general / unsupported), the single
  primary next action keyed to reader stage, bounded revision, the "decide, do not ask"
  rule for unattended runs, self-scores-are-not-evidence, changing-claims-need-current-
  evidence, the explicit owner-decision surfacing check and a handoff packet.
- Each specialist pack: required inputs with declared missing behaviour; ordered
  decision steps ending in an explicit handoff step naming the next stage and what may
  not pass (publication, send, scheduling, unapproved terms); operational rules with
  stable ids (<pack>.<kebab>); receipt fields including audience, purpose, format or
  structure, angle, evidence references and next action where relevant; inspectable
  quality checks with a failure action; a revision policy of one or two passes.
- Compatibility: editorial-planning returns the existing one-pillar-plus-six cluster with
  the existing fields; blog-writing respects seo_title ≤65, meta 70–160, 3–10 sections,
  0–6 FAQs, [src:ID] figure markers, allowed-links-only, Markdown-only bodies and neutral
  image_alt; social-repurposing preserves the two-post default and the six_angle_campaign
  recipe (launch/takeaway/follow_up × instagram/linkedin, ~40–70 words, one-sentence art
  brief, no URL, no publication claim); visual-briefing fits the existing image-brief
  fields; email-writing and offer-design are authoring contracts with no runtime path
  claimed.
- Examples: two fictional brands per pack (a home-maintenance business and a B2B
  scheduling business) with explicitly invented facts and no performance evidence,
  showing the same method with separate facts, voice and calls to action.

3. SOURCE VARIANTS — DECISIONS AND RECOMMENDATIONS
a) 40/30/20/10 content mix (original) vs optional (newer master).
   Implemented as: optional guidance. editorial-planning treats any supplied mix as a
   target to approach and records deviations; with no guidance it uses a recorded default
   (majority learn, at least one compare or buy per cluster). Recommendation: keep it
   optional. A fixed quota forces unsupported or duplicated topics, which the platform's
   factual rules then reject anyway.
b) Social manual-input vs Make.com-enabled variants.
   Implemented as: neither. social-repurposing produces drafts for the existing exact-
   version approval path only and forbids implying any integration, platform or format
   the runtime has not confirmed. Recommendation: do not model either variant; the
   platform's own calendar and registry gates are the integration.
c) Root AI Training Docs template containing Prop Invest content.
   Implemented as: excluded. No Prop Invest or Property Predator fact, audience
   assumption, price, CTA or model appears in any pack; a brand's lifecycle model is
   treated as optional brand context only. Recommendation: keep brand material in brand
   packs; never promote it to a generic method.
d) Newer manuals as working source, not automatic approval.
   Implemented as: every pack is draft and its provenance says private-use and public
   approval are separate recorded decisions.

4. MATERIAL DELIBERATELY OMITTED
- No mandatory word counts (social lengths are the existing stage ceiling, not a quota),
  no content quotas, no required testimonials, urgency, discounts, outcome claims or case
  studies. Case studies are allowed only when verified brand evidence exists.
- No framework stacking: conversion-copy selects one structure per asset.
