# Generated drafts that survive navigation

Campaign Builder now saves each generated channel as an immutable HQ content
version before showing success. A text-only single draft opens its exact saved
review; channel packs link to each saved version and the existing library.
Generation does not approve, schedule or publish any content.

Retries retain the workspace, command, brief, plan, brand and exact approved
source identities. Volatile observation times do not create a second generation
or persistence command. Partial failures offer a retry of only the failed
channels. A changed approval tuple stops that retry before generation.

Prepared media remains visible in the immediate review and failed-channel retry.
It is explicitly a preview, not part of the saved text version or its approval.
Durable media attachment and editing generated copy require a later verified
versioning workflow. There is no new pack aggregate or migration.

The adapter must have its existing exact append-only content capabilities before
generation is enabled. It cannot approve content or create provider operations.
Selected evidence records the historical preflight and post-generation checks;
these checks do not claim that an approval remains current indefinitely.

Verification includes router, lifecycle, replay and tenant tests; TypeScript
checking; and a real PostgreSQL proof on an isolated child of the HQ database.
The latter used direct adapter, web and command roles to save, reopen, replay and
verify approval gates with a fake generator and zero outbound operations.
Append-only synthetic fixtures remain on that disposable child; production was
not written by the proof. Exact suite totals and release status are recorded in
the workspace overnight BUILD-STATE.
